# Design

## Context

Паттерн блокировки уже реализован для проектов (`project-lock`): флаг в записи, guard в хранилище, кнопка-замок с confirm в обе стороны, неактивная ✕. Запросы хранятся в `requests[]` файла проекта; вкладки связаны через `savedRequestId`; Save идёт через `saveTab` → `saveRequest` (upsert по id). Контекстное меню вкладки содержит «Сохранить».

## Goals / Non-Goals

**Goals:**
- Защита сохранённой записи от обновления и удаления; UI-подсказки; персистентность.

**Non-Goals:**
- Read-only вкладки (мягкая блокировка — выбрана пользователем), пароль на разблокировку, блокировка секций, индикатор блокировки в тулбаре.

## Decisions

### D1. Флаг в записи запроса, отсутствует = false
`locked` — часть записи запроса в `requests[]` (как у проекта в индексе). Обратная совместимость без миграции: единственная проверка `locked === true`. Snapshot вкладки не содержит `locked` — это метаданные записи, не поля запроса: `saveRequest` принимает флаг только через `setRequestLocked`, upsert сохраняет прежнее значение флага (или false для нового).

### D2. Guard в `saveRequest` — только для существующего id
`saveRequest` находит запись по `request.id`: если запись существует и `locked === true` → ошибка «Запрос заблокирован» до мутаций. Если id не найден (новый запрос — клон, импорт-сохранение) — создаётся свободно. Это даёт «лазейку»: клонирование разблокировывает правки, сохранение клона — новый запрос. `deleteRequest`: `locked === true` → ошибка «Запрос заблокирован» до записи.

### D3. IPC `requests:setLocked` по паттерну проекта
`(event, {projectId, requestId, locked})` → обновлённый `requests[]` (единый источник правды, как list/save/delete). Валидация: запрос существует, `locked` — boolean.

### D4. Save-кнопка неактивна по связи вкладки
Активная вкладка связана с заблокированным запросом (`requests.items.find(r => r.id === tab.savedRequestId)?.locked === true`) → `canSave` false, tooltip; контекстный пункт «Сохранить» аналогично. Проверка в `saveTab` дублирует guard: связанная вкладка не сможет сохранить даже из меню `CmdOrCtrl+S`. Несвязанные вкладки и клоны не затронуты.

### D5. UI — зеркалирование project-lock
Кнопка-замок 🔓/🔒 третьей в actions строки запроса (до ✕), confirm обе стороны (`AppDialog.confirm`), 🔒-индикатор у имени, ✕ `:disabled` + tooltip. Unicode-глифы, без зависимостей.

## Risks / Trade-offs

- [Пользователь правит связанную вкладку, Save заблокирован — правки «висят» без сохранения] → dirty-точка видна, tooltip объясняет; лазейка — клон. Осознанный выбор мягкой блокировки.
- [Молча перезаписать нельзя, но можно удалить проект целиком] → удаление проекта — отдельная операция со своим confirm; задокументировано в proposal.
- [Множественные вкладки одного заблокированного запроса] → все получают неактивный Save (проверка по связи) — единообразно.
