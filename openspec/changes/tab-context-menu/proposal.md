# Proposal

## Why

Действия сохранения и клонирования доступны только через кнопку Save (для активной вкладки) и «+» (пустая вкладка). Правый клик по вкладке — привычный жест для операций над конкретным элементом: он позволяет сохранить или клонировать любую вкладку, не делая её активной.

## What Changes

- Контекстное меню вкладки запроса (правый клик): действия «Сохранить» и «Клонировать», применяемые к кликнутой вкладке.
- Меню — веб-стиль (HTML-компонент в стиле приложения), без нативного `Menu.popup` и без новых IPC.
- «Сохранить» из меню работает по правилам сохранения: связанная вкладка обновляется молча, несвязанная — через диалог имени; действие неактивно без активного проекта.
- «Клонировать» создаёт новую вкладку с полной копией содержимого кликнутой (params/headers/body/auth/sslVerify), без связи с сохранённым запросом, с именем «имя (копия)»; клон становится активной вкладкой, и его первый Save создаёт новый запрос в проекте.

Вне scope: другие пункты меню (переименование, закрытие, закрыть прочие); контекстное меню в сайдбаре; нативное системное меню.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `request-storage`: ADDED требования «Контекстное меню вкладки запроса» — открытие меню правым кликом, сохранение кликнутой вкладки из меню, клонирование в несвязанную копию.

## Impact

- `src/renderer/src/components/ContextMenu.vue` — новый компонент веб-меню (позиционирование у курсора, закрытие по клику вне/Esc/после действия).
- `src/renderer/src/components/RequestTabs.vue` — обработка `contextmenu` на вкладке с передачей tabId.
- `src/renderer/src/stores/tabs.js` — рефакторинг `saveActiveViaDialog(dialog)` → `saveTab(id, dialog)`, новый `cloneTab(id)`.
- `src/renderer/src/assets/style.css` — стили меню.
- Зависимости не добавляются. `app-shell` не затрагивается (меню — поведение, не раскладка).
