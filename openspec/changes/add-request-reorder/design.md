# Design

## Context

Порядок запросов — это порядок массива `requests[]` в `projects/<id>.json`; отдельного поля сортировки нет. Каналов IPC для переупорядочивания нет (`requests:list/save/delete/setLocked`). Список рендерится в `RequestList.vue` простым `v-for` по `requests.items`. Спека блокировки запроса ограничивает только сохранение изменений и удаление; блокировка проекта (спека projects-management) — только удаление, поэтому ни один замок не мешает менять порядок массива. В `RequestTabs.vue` есть отлаженный pointer-drag вкладок: window-слушатели вместо `setPointerCapture` (capture снимается неявно при DOM-перемещении узла — выученный урок change `add-tab-drag-and-pin`), порог 4px, live-swap по серединам соседей.

## Goals / Non-Goals

**Goals:**
- Перетаскивание строк запросов в сайдбаре с сохранением порядка на диск (переживает перезапуск).
- Заблокированная строка не является drag-источником; замки сдвигаются при drag других без изменения содержимого.
- Одна атомарная запись файла на завершение drag.

**Non-Goals:**
- Drag между проектами, папки/группы, сортировка по заголовку, перемещение окружений.
- Виртуализация списка (проекты локальные, сотни запросов — не случай этого приложения).
- Анимации перестановки (live-swap, как во вкладках).

## Decisions

### 1. Хранилище: `reorderRequests(projectId, requestId, toIndex)`
Функция в `storage.js`: читает файл проекта, валидирует `toIndex` (0..length-1), `splice(from,1)` + `splice(to,0,tab)` по `id`, атомарная запись (tmp+rename, как все мутации). Ограничений на `locked` **нет** — ни на источник, ни на сдвигаемых: перемещение не меняет содержимое запроса, а спеки обоих замков этого не запрещают. Заблокированный источник отсекается на уровне UI. Возвращать обновлённый `requests[]` (паттерн всех запросов хранилища — store не расходится с диском).

### 2. Диск — один вызов на pointerup
Во время drag порядок меняется локально (`splice` в `requests.items` — живая реактивная перестановка), на отпускание — один IPC `requests:reorder` (id + итоговый индекс), ответ обновляет `items`. Одна атомарная запись вместо записи на каждый swap; сбой IPC → `requests.load(projectId)` (откат к состоянию диска). Отмена drag (`Escape`/`pointercancel`) — тоже rollback через `load`.

### 3. Drag в `RequestList.vue` — перенос приёмов из вкладок
Pointer-слой по образцу `RequestTabs.vue`: порог 4px, слушатели `pointermove/up/cancel` на `window` (без `setPointerCapture` — урок вкладок), live-swap по серединам соседних строк по вертикали. Отличия:
- `pointerdown` на строке заблокированного запроса drag не начинает вовсе (guard до записи состояния) + `cursor: grab` только на незаблокированных строках — состоянию «нельзя» не нужен отдельный диалог;
- кнопки-действия строки (замок, удаление) останавливают `pointerdown` на себе, как `×`/булавка во вкладках;
- после активного drag подавляется синтезированный `click` (флаг-гард в `open`) — на вкладках активация была безвредна, здесь click после drag открыл бы запрос неожиданно.

### 4. IPC: канал `requests:reorder` по существующему паттерну
`ipcMain.handle('requests:reorder', (_e, { projectId, requestId, toIndex }) => storage.reorderRequests(...))`, мост в preload `requests.reorder(projectId, requestId, toIndex)`. Префикс `requests:*` соответствует конвенции каналов в AGENTS.md. Валидация типов аргументов в хранилище (как у `setRequestLocked`).

### 5. Автоскролл сайдбара
Список запросов может переполнять сайдбар по вертикали — при drag у верхней/нижней границы зоны списка включается автоскролл (rAF, шаг за кадр, стоп на `pointerup`), как горизонтальный у вкладок. Если в верстке сайдбара скроллится контейнер выше уровнем, порог считается по его rect.

## Risks / Trade-offs

- [click после drag открывает «брошенный» запрос] → флаг-гард в `open`, сбрасывается первым не-drag кликом.
- [Расхождение `items` с диском во время drag (до IPC)] → окно между swap и pointerup — доли секунды; любой сбой закрывается `load`; параллельных писателей списка в одном процессе нет.
- [Пользователь ожидает «замок = неприкасаемая позиция»] → осознанное решение explore-сессии: блокировка защищает содержимое (спека), а не позицию; иначе часть порядка недостижима.
- [Сайдбар скроллится не самим `ul`] → задача автоскролла стартует с проверки rect-а контейнера в apply; шаг не меняется.

## Migration Plan

Новый канал и новая функция — обратной совместимости не ломают; старые `settings.json`/файлы проектов не меняются. Откат — revert коммита.
