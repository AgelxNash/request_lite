# Design

## Context

Порядок вкладок — это порядок массива `tabs` в сторе `tabs.js` (см. proposal.md — Why). Мутации сегодня: `push` в конец (открытие/клон/импорт) и `splice` на закрытие; рендер — простой `v-for` в `RequestTabs.vue`. Контекстное меню таргетит кликнутую вкладку, но пунктов закрытия в нём нет — закрытие только через `×`. Полоса вкладок — `display: flex; overflow-x: auto`, вкладка `max-width: 220px`. В renderer только `pinia` и `vue`; проектные конвенции — свои лёгкие реализации вместо библиотек (curl-парсер, подсветка JSON).

## Goals / Non-Goals

**Goals:**
- Перетаскивание вкладок с порогом «клик vs drag» (~4px) и живой перестановкой при пересечении середины соседа — как в Chrome/Postman.
- Инвариант «закреплённые первыми» на уровне стора: рендер и логика закрытия остаются неизменными (`v-for` по массиву, `closeTab` по индексам).
- Pin/unpin: контекстное меню, двойной клик, клик по иконке булавки; drag через границу зон меняет pin.
- Автоскролл полосы при drag у краёв.

**Non-Goals:**
- Session restore открытых вкладок и pin-состояния между запусками (вкладки сегодня не персистируются вовсе — отдельное изменение).
- Горячие клавиши для pin/reorder; закрытие «все кроме этой»; многооконность.
- FLIP-анимации перестановки (живой swap достаточно, анимацию можно добавить позже).
- Изменения main-процесса, IPC, хранилища, снимка запроса.

## Decisions

### 1. Pointer Events вместо HTML5 Drag&Drop
`pointerdown` на вкладке → слушатели `pointermove`/`pointerup`/`pointercancel` на `window` (без `setPointerCapture`).
Альтернатива — нативный `draggable`: не даёт порога (drag стартует мгновенно и конфликтует с кликом), использует системный призрак-скриншот, автоскролл всё равно дописывать вручную. Pointer-события дают полный контроль при ~100 строках и соответствуют проектной конвенции «свои лёгкие реализации».

Амденд (по итогам ручной проверки): изначально использовался `setPointerCapture` на самой вкладке, но живая перестановка перемещает DOM-узел вкладки, а capture при удалении из дерева снимается неявно — после первого swap события переставали приходить и drag зависал (подтверждено минимальным воспро в Chromium). Слушатели на `window` работают и с перестановками, и над промежутками/кнопкой «+».

Механика drag:
- Порог 4px по суммарному смещению до старта drag; до порога — ничего, после — вкладка получает класс `dragging` (лёгкий lift: масштаб/тень/полупрозрачность).
- Живая перестановка: на каждом `pointermove` целевой визуальный индекс вычисляется сравнением курсора с серединами соседних вкладок; при изменении вызывается экшен стора — DOM обновляется реактивно без FLIP.
- Граница зон жёсткая: drag не меняет закрепление (решение пересмотрено после ручной проверки — модель Chrome с откреплением перетаскиванием отклонена пользователем). `moveTab` зажимает целевую позицию в зону вкладки: закреплённая не уходит правее последней закреплённой, обычная не встаёт в зону pin. Pin/расpin — только меню, двойной клик и иконка булавки.
- `×`, иконка булавки и контекстное меню не начинают drag (`pointerdown` с `stopPropagation` на этих элементах); открытие контекстного меню во время drag отменяет drag.
- Ложный `click` после drag не гасится: без capture он уходит на общего предка (строку вкладок), а click на самой вкладке после жеста — это штатная активация.
- `pointercancel` и `Escape` — аккуратное завершение drag; исходный порядок не восстанавливается (перестановки уже применены — это осознанный выбор, как в Chrome).

### 2. Нормализация зон в сторе, а не сортировка на рендере
Экшены стора после любой мутации поддерживают инвариант «все `pinned` идут первыми» (стабильная перестановка). Альтернатива — вычислять порядок в getter'е при рендере: два источника истины, drag-код всё равно должен маппить визуальные индексы в массив, сложнее рассуждать о `closeTab`/`activeTab`.

API стора:
- `moveTab(id, toVisualIndex)` — целевой индекс в визуальных терминах (0..tabs.length-1); стор переводит в индексы массива с учётом зоны и нормализует.
- `togglePin(id)` — переключает `pinned`; закреплённая встаёт на край своей новой зоны (pin → после последней закреплённой, unpin → перед первой обычной), относительный порядок остальных сохраняется.
Клик по булавке = `togglePin`; drag = серия `moveTab`.

### 3. Модель: `pinned` — UI-поле вкладки
`pinned: false` в `makeTab()`; в `toSnapshot()` не попадает (снимок — модель запроса, зафиксирована в `request-storage`); `openTabFromSnapshot` и `cloneTab` создают незакреплённые вкладки (дефолт `makeTab`), клон встаёт в конец.

### 4. UX закреплённой вкладки
- Иконка булавки — inline SVG (без эмодзи и зависимостей), стоит на месте `×`; клик по ней = `togglePin` (вкладка не активируется).
- Крестик скрыт у закреплённых; в контекстное меню добавляются «Закрепить»/«Открепить» (лейбл по состоянию) и «Закрыть вкладку» (у всех вкладок — закрывает пробел: сегодня закрытие только через `×`).
- Двойной клик по вкладке — `togglePin` (как в VS Code); конфликтов нет — `dblclick` нигде не занят.
- Индикатор `dirty` (•) остаётся видимым на закреплённых вкладках.

### 5. Автоскролл полосы
На `pointermove` в пределах ~24px от левого/правого края `tabs-strip` — плавная прокрутка (шаг за кадр через `requestAnimationFrame`), останавливается на `pointerup`/`pointercancel`. Без неё скрытые за скроллом позиции недостижимы (полоса с `overflow-x: auto`).

## Risks / Trade-offs

- [click срабатывает после pointerup] → без capture click уходит на общего предка (строку), а не на «брошенную» вкладку; активация штатная.
- [Живой swap без FLIP выглядит «резким» по сравнению с Postman] → осознанный trade-off простоты; CSS-переход на transform можно добавить позже без изменений API стора.
- [Capture на перемещаемом DOM-узле теряется] → решено: слушатели на `window`, capture не используется (см. амденд в решении 1).
- [Автоскролл может «убежать» при резком движении курсора] → шаг прокрутки фиксированный и малый; drag-индекс пересчитывается каждый кадр.
- [Смоук-тесты не покрывают renderer] → фича целиком в renderer; проверка — ручной e2e-чеклист из tasks.md (AGENTS.md: ручной e2e обязателен при изменениях UI).

## Migration Plan

Изменения только в renderer, хранилище и IPC не затронуты — миграции нет. Откат — revert коммита.

## Open Questions

Нет — развилки (модель зон, реализация drag, закрытие закреплённых) решены в explore-сессии.
