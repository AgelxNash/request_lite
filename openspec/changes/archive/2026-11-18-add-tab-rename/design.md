# Design

## Context

Имя вкладки — часть модели запроса (`name` в `toSnapshot`), но меняется сегодня только косвенно: при сохранении (`tab.name = name`), клонировании («(копия)») и открытии запроса. Подстановка имени переименованной вкладки в диалог сохранения уже реализована в `saveTab` (предпочитает `tab.name !== 'Untitled Request'` имени из URL) и простаивает без UI переименования. Диалог prompt переиспользуется в проекте дважды: переименование проектов и сохранение запроса. Индикатор точки в коде показывается на любой вкладке с `dirty: true`, тогда как спека `request-storage` ограничивала её связанными вкладками — существующий дрейф, который задевает данное изменение (см. proposal.md — Capabilities).

## Goals / Non-Goals

**Goals:**
- Переименование вкладки: пункт меню + двойной клик по имени, диалог `dialog.prompt`, без новых зависимостей и без IPC.
- Честный индикатор: rename ставит `dirty`, точка исчезает после сохранения (уже работающая механика).
- Спека `request-storage` фиксирует приоритет подстановки и выравнивается с кодом по точке.

**Non-Goals:**
- Inline-редактирование в самой вкладке (input в узкой вкладке с эллипсисом, фокус/blur-возня — окупится редко при готовом диалоге).
- Переименование сохранённых запросов из сайдбара, горячие клавиши (F2 и т.п.).
- Массовые операции (переименовать все/кроме).

## Decisions

### 1. Стор: один экшен `renameTab(id, name)`
Меняет `name` и ставит `dirty = true`; валидация пустого имени — на уровне UI (отмена диалога). Разделение ответственности: компонент владеет диалогом (как `saveTab` получает `dialog` параметром, а `ProjectList` вызывает `dialog.prompt` сама), стор — состоянием.

### 2. Двойной клик только по имени вкладки
Обработчик `@dblclick` вешается на `span.tab-name` с `stopPropagation` — двойной клик по остальной вкладке остаётся закреплением/откреплением (фича `add-tab-drag-and-pin`). Область клика совпадает с отображаемым именем (с эллипсисом при переполнении) — достаточно, меню дублирует действие. `title` вкладки и так подсказывает имя, подсказка «двойной клик — переименовать» на `tab-name` добавит обнаруживаемость.

### 3. Пункт меню «Переименовать» — после «Сохранить»
Порядок: Сохранить, Переименовать, Клонировать, Закрепить/Открепить, Копировать как cURL, Закрыть вкладку. Переименование доступно и для связанной вкладки с заблокированным запросом: это локальное изменение вкладки, ограничения блокировки касаются только сохранения (Save остаётся неактивным, как сейчас).

### 4. Подстановка при сохранении уже реализована — только формализация
`saveTab` предпочитает имя переименованной вкладки; после первого сохранения `tab.name` становится именем запроса, повторное сохранение связанной вкладки идёт без диалога и молча подхватывает переименование. В спеку `request-storage` добавляется только явный приоритет «имя переименованной вкладки → URL» и сценарий.

### 5. Выравнивание требования «Индикатор несохранённых изменений» с кодом
Спека ограничивала точку связанными вкладками, но код показывает её на любой `dirty`-вкладке (переименование, правки черновика). MODIFIED-дельта убирает исключение и добавляет сценарий переименования — спека перестаёт расходиться с наблюдаемым поведением в том месте, на которое опирается данное изменение.

## Risks / Trade-offs

- [Двойной клик по имени срабатывает и на активации вкладки (два click перед dblclick)] → безвредно: вкладка и так активируется, переименование открывается поверх.
- [Пункт меню на закреплённой вкладке рядом с «Открепить» — действия визуально смешиваются] → разные подписи, конфликтов логики нет; rename работает на закреплённых так же.
- [Смоук не покрывает renderer] → проверка ручным e2e-чеклистом (AGENTS.md), как в предыдущих UI-изменениях.

## Migration Plan

Хранилище и IPC не затронуты; откаты — revert коммита. Изменение веткуется стеком на `feat/tab-drag-and-pin` (общие файлы: меню, шаблон вкладки, `tabs.js`).

## Open Questions

Нет — развилки (способ переименования, dirty-семантика) решены в explore-сессии.
