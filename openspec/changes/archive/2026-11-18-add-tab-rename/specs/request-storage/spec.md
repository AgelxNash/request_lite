# Spec Delta: request-storage

## MODIFIED Requirements

### Requirement: Сохранение запроса в активный проект
Кнопка Save в строке запроса и пункт меню Save Request (`CmdOrCtrl+S`) SHALL сохранять снимок запроса из активной вкладки в активный проект. При первом сохранении несвязанной вкладки SHALL запрашиваться имя запроса (диалог с предзаполнением имени: имя переименованной вкладки, если вкладка была переименована, иначе имя из URL); повторное сохранение связанной вкладки обновляет тот же запрос без диалога. Если активного проекта нет, Save SHALL быть недоступен. Обновление заблокированного запроса SHALL отклоняться: Save связанной с заблокированным запросом вкладки неактивен с подсказкой, а хранилище отклоняет upsert существующего заблокированного запроса; создание нового запроса не ограничивается.

#### Scenario: Первое сохранение с диалогом имени
- **WHEN** пользователь нажимает Save на несвязанной вкладке с URL `https://example.com/api`
- **THEN** открывается диалог с именем, предзаполненным из URL, и после подтверждения запрос появляется в сайдбаре активного проекта, вкладка связывается с ним

#### Scenario: Переименованная вкладка подставляет своё имя
- **WHEN** пользователь переименовал несвязанную вкладку в «Логин» и нажимает Save
- **THEN** диалог имени предзаполнен «Логин», а не именем из URL, и после подтверждения запрос сохраняется под этим именем

#### Scenario: Повторное сохранение без диалога
- **WHEN** пользователь меняет URL связанной вкладки и снова нажимает Save
- **THEN** сохранённый запрос в проекте обновляется без диалога имени

#### Scenario: Нет активного проекта
- **WHEN** в приложении нет ни одного проекта
- **THEN** кнопка Save неактивна

#### Scenario: Save неактивен для связанной вкладки заблокированного запроса
- **WHEN** вкладка связана с заблокированным запросом, и пользователь наводит курсор на кнопку Save
- **THEN** кнопка Save и пункт меню «Сохранить» неактивны с подсказкой «Запрос заблокирован — разблокируйте, чтобы сохранить»

#### Scenario: Хранилище отклоняет обновление заблокированного
- **WHEN** запрос на обновление существующего заблокированного запроса достигает хранилища (минуя UI)
- **THEN** сохранение отклоняется с ошибкой, запись остаётся неизменной

#### Scenario: Создание нового запроса не ограничено
- **WHEN** пользователь сохраняет несвязанную вкладку или клон под новым именем
- **THEN** новый запрос создаётся как обычно

### Requirement: Индикатор несохранённых изменений
После изменения содержимого любой вкладки — связанной или несвязанной — SHALL появляться индикатор (точка) на её вкладке; переименование вкладки также помечает её индикатором. После успешного сохранения индикатор исчезает.

#### Scenario: Точка после изменения
- **WHEN** пользователь меняет URL в связанной вкладке
- **THEN** на вкладке отображается точка

#### Scenario: Точка на несвязанной вкладке
- **WHEN** пользователь меняет URL в несвязанной вкладке
- **THEN** на вкладке отображается точка

#### Scenario: Точка после переименования
- **WHEN** пользователь переименовывает вкладку
- **THEN** на вкладке отображается точка, и она исчезает после успешного сохранения

#### Scenario: Точка исчезает после сохранения
- **WHEN** пользователь сохраняет вкладку с точкой
- **THEN** точка исчезает
