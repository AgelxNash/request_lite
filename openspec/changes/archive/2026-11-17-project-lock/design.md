# Design

## Context

Проекты хранятся двумя сущностями: индекс `projects.json` (`{id, name, createdAt, updatedAt}`) и файлы `projects/<id>.json` (данные). Удаление идёт через `deleteProject` (main) после `AppDialog.confirm` в UI. Строка проекта в `ProjectList.vue` уже содержит actions (✎/✕) с show-on-hover.

## Goals / Non-Goals

**Goals:**
- Флаг-переключатель с подтверждением, защита удаления на двух уровнях (UI + main), персистентность.

**Non-Goals:**
- Пароль/пин на разблокировку, блокировка запросов/окружений, аудит блокировок, групповые операции.

## Decisions

### D1. Флаг в индексе, не в файле проекта
`locked` — метаданные управления, а не данные запросов: живут в записи `projects.json`. «Можно ли удалять» должно читаться без чтения файла проекта (`deleteProject` guard проверяет индекс до `rm`). Обратная совместимость: отсутствующее поле = `false` (`project.locked === true` — единственная проверка), миграция не нужна.

### D2. Guard в `deleteProject` — второй рубеж
UI-дизейбл кнопки — первичная защита, но канал `projects:delete` доступен минуя UI: `deleteProject` проверяет `locked` и бросает ошибку «Проект заблокирован». Порядок: проверка до записи индекса и до `rm` — при отклонении ничего не мутируется.

### D3. IPC — `projects:setLocked` по паттерну rename
`(event, {id, locked})` → возвращает обновлённую запись проекта (как `rename`). Renderer store (`projects.setLocked`) обновляет запись в списке локально из ответа. Валидация: проект существует, `locked` — boolean.

### D4. UI-паттерн — третья кнопка в actions
Кнопка-замок перед ✎: иконка 🔒 (заблокирован) / 🔓 (нет) — состояние видно всегда (actions показываются on-hover/active, но для заблокированного замок виден и через индикатор у имени). ✕ получает `:disabled` + `title="Проект заблокирован"`. Подтверждение — `AppDialog.confirm` (danger-стиль не нужен для блокировки; для разблокировки тоже обычный confirm).

### D5. Иконки — Unicode-глифы как в остальном UI
Проект уже использует ✎/✕/+/⚙/🔒-подобные глифы: замок — `🔒`/`🔓`, индикатор у имени — `🔒` перед именем (маленький, secondary-цвет). Без иконочных зависимостей.

## Risks / Trade-offs

- [Индикатор-глиф зависит от шрифта системы] → Unicode 🔒 широко поддержан; fallback — текстовый префикс не критичен.
- [Guard в main отклоняет и легитимные сценарии при потере UI-состояния] → guard читает актуальный индекс с диска, а не кэш UI — расхождение исключено.
- [Confirm на оба направления — лишний клик при частых переключениях] → осознанно: блокировка защищает от случайностей, обе операции должны быть явными.

## Migration Plan

Не требуется: поле отсутствует = разблокирован.
