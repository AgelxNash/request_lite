# Spec Delta: app-shell

## MODIFIED Requirements

### Requirement: Окно и раскладка в стиле Postman
Приложение SHALL открывать главное окно с раскладкой из трёх зон: тулбар сверху, сайдбар проектов слева, основная область (редактор запроса + область ответа) справа. В тулбаре SHALL быть переключатель видов основной области: «Запросы» и «Мок-сервер». Выбранный вид является runtime-состоянием сессии и SHALL сбрасываться к виду «Запросы» при перезапуске приложения.

#### Scenario: Первый запуск на пустом хранилище
- **WHEN** пользователь запускает приложение, а папка хранилища пуста
- **THEN** окно открывается с полной раскладкой, сайдбар показывает пустое состояние с приглашением создать проект

#### Scenario: Состав тулбара
- **WHEN** пользователь смотрит на тулбар
- **THEN** в нём видны название приложения, переключатель видов «Запросы | Мок-сервер», рабочий селектор окружения (окружения активного проекта и «No Environment») с кнопкой управления окружениями, кнопка переключения темы

#### Scenario: Переключение видов основной области
- **WHEN** пользователь выбирает другой вид в переключателе
- **THEN** основная область и сайдбар показывают содержимое выбранного вида

#### Scenario: Вид сбрасывается при перезапуске
- **WHEN** пользователь работал на виде «Мок-сервер» и перезапускает приложение
- **THEN** приложение открывается на виде «Запросы»

### Requirement: Редактор и ответ как каркасные зоны
При виде «Запросы» основная область SHALL показывать строку вкладок открытых запросов, строку метод + URL + Save + Send, вкладки запроса (Params, Headers, Body, Auth) и область ответа. При виде «Мок-сервер» основная область SHALL показывать панель мок-сервера, а сайдбар SHALL показывать список мок-проектов вместо проектов запросов. Поведение вкладок запроса, сохранения и отправки определяется capabilities `request-storage` и `request-execution`; поведение мок-сервера определяется capability `mock-server`; данное требование описывает только состав и раскладку зон.

#### Scenario: Вкладка открытого запроса
- **WHEN** открыта одна стартовая вкладка запроса
- **THEN** она отображается на строке вкладок и может быть закрыта

#### Scenario: Пустое состояние до логики запросов
- **WHEN** пользователь открывает основную область до первой отправки запроса
- **THEN** вкладки запроса отображаются, а область ответа показывает пустое состояние

#### Scenario: Состав основной области
- **WHEN** пользователь открывает основную область на виде «Запросы»
- **THEN** строка метод + URL + Save + Send, вкладки запроса и область ответа отображаются друг под другом

#### Scenario: Состав основной области при виде «Мок-сервер»
- **WHEN** пользователь переключает вид на «Мок-сервер»
- **THEN** основная область показывает панель мок-сервера (статус сервера, порт и кнопки запуска/остановки, редактор маршрутов, журнал запросов), а сайдбар показывает список мок-проектов с кнопкой создания

#### Scenario: Возврат на вид «Запросы»
- **WHEN** пользователь переключается обратно на вид «Запросы»
- **THEN** сайдбар снова показывает проекты и запросы, редактор запроса восстанавливает открытые вкладки запросов
