# Proposal: Встроенный мок-сервер (вторая вкладка «Мок-сервер»)

## Why

Для ручного e2e и отладки внешних интеграций нужен локальный HTTP-сервер с управляемыми JSON-ответами и журналом входящих запросов. Сейчас он есть только как внешний CLI-скрипт (`scripts/mock-server.mjs`): конфиг правится руками в файле, журнал живёт в терминале, ничего не сохраняется в приложении. Встраивание в Request Lite даёт управление из UI, сохраняемые конфигурации и живой журнал — по образцу того, как MCP-сервер уже живёт в main-процессе.

## What Changes

- В основной области появляется переключатель видов «Запросы | Мок-сервер» (второй таб).
- Новая сущность **мок-проект**: свой CRUD в хранилище (создание, переименование, удаление, список), набор маршрутов и ответ по умолчанию; хранится в JSON-файлах как у проектов запросов.
- Встроенный HTTP-сервер в main-процессе: **один активный экземпляр** — пользователь выбирает мок-проект и порт, Start/Stop; конфликт порта → статус ошибки; правки маршрутов применяются к запущенному серверу без рестарта.
- Редактор маршрутов в UI: method, path, status, заголовки ответа, тело (raw), задержка `delayMs`; плюс ответ по умолчанию для неотматченных запросов.
- Живой журнал принятых запросов в UI: метод, путь, заголовки, тело; буфер с лимитом, очистка.
- Новые IPC-каналы с префиксом `mocks:*` + push-канал журнала из main в renderer.
- Смоук-тесты: CRUD мок-проектов в storage, жизненный цикл сервера, обработка запросов, журнал.

Вне скоупа (v1): админ-API `/__admin`, несколько одновременных серверов, подстановка `{{var}}` в мок-ответах, drag/закрепление/блокировка у мок-проектов, persist-журнал на диск. Внешний `scripts/mock-server.mjs` остаётся как есть.

## Capabilities

### New Capabilities
- `mock-server`: хранение мок-проектов и маршрутов, жизненный цикл встроенного сервера (старт/стоп/статус/порт), обработка входящих запросов по конфигу маршрутов, журнал входящих запросов, UI вкладки «Мок-сервер» (редактор маршрутов, управление сервером, журнал).

### Modified Capabilities
- `app-shell`: основная область получает переключатель видов «Запросы | Мок-сервер»; при виде «Мок-сервер» сайдбар показывает список мок-проектов, а основная область — панель мок-сервера (управление сервером, редактор маршрутов, журнал) вместо редактора запроса и ответа.

## Impact

- **main**: новый `src/main/mock.js` (сервер + журнал, без зависимости от Electron — по образцу `mcp.js`), расширение `src/main/storage.js` (мок-проекты), `src/main/ipc.js` (каналы `mocks:*`), `src/main/index.js` (bootstrap/stop при выходе, push-канал журнала).
- **preload**: расширение `window.api` неймспейсом `mocks` + подписка на push-журнал.
- **renderer**: новый store `mocks.js`, компоненты вкладки мок-сервера (список мок-проектов в Sidebar, панель: статус/порт/Start-Stop, редактор маршрутов, журнал), переключатель видов в `Toolbar.vue`/`App.vue`, состояние вида в `ui.js`.
- **Хранилище**: `mock-projects.json` (индекс) + `mock-projects/<id>.json` (маршруты, ответ по умолчанию) рядом с существующими файлами; `settings.json` — без изменений (порт и активный сервер — runtime-состояние `mock.js`, не настройки).
- **Тесты**: блок «Мок-сервер» в `scripts/smoke.mjs` (импорт `src/main/mock.js` в чистом Node).
- **Документация**: AGENTS.md — префикс `mocks:*` в списке каналов, push-канал журнала, файлы хранилища.
