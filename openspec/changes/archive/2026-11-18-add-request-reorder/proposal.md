# Proposal

## Why

Порядок запросов в проекте фиксирован порядком добавления: часто используемый запрос нельзя поставить первым, связанные по задаче не сгруппировать. С ростом проекта список становится трудночитаемым. Порядок уже хранится как порядок массива `requests[]` в файле проекта — не хватает операции перестановки и её UI.

## What Changes

- Перетаскивание запросов в списке «Запросы» сайдбара для смены порядка: pointer-drag по образцу вкладок (порог клик-vs-drag, живая перестановка, window-слушатели без pointer capture).
- Заблокированный запрос нельзя перетащить как источник (drag на нём не начинается), но незаблокированные могут перемещаться мимо него: заблокированный сдвигается в списке, его содержимое не меняется — соответствует спеке блокировки (ограничивает только сохранение изменений и удаление).
- Новый IPC-канал `requests:reorder` + функция в хранилище: порядок сохраняется на диск одной атомарной записью по завершении drag и переживает перезапуск.
- Блокировка проекта не влияет на перемещение запросов (спека projects-management: блокировка проекта ограничивает только удаление).

Вне скоупа: drag между проектами, папки/группы запросов, сортировка кликом по заголовку, перемещение окружений.

### Modified Capabilities

- `request-storage`: модифицируется «Список запросов проекта в сайдбаре» (сейчас — «в порядке добавления», становится — порядок, заданный пользователем); добавляется «Перемещение запросов» — drag-механика, взаимодействие с блокировкой, сохранение порядка между запусками.

## Impact

- `src/main/storage.js` — функция `reorderRequests(projectId, requestId, toIndex)` с атомарной записью файла проекта.
- `src/main/ipc.js` + `src/preload/index.js` — канал `requests:reorder`, мост `window.api.requests.reorder`.
- `src/renderer/src/stores/requests.js` — экшен `reorder`.
- `src/renderer/src/components/RequestList.vue` — pointer-drag в вертикальном списке.
- Скрипт smoke — тесты функции переупорядочивания хранилища (CRUD-секция уже тестирует хранилище).
