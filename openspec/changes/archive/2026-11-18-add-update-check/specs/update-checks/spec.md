# Spec Delta: update-checks

## Purpose

Приложение должно сообщать пользователю о выходе новой версии: проверять публичный фид обновлений, сравнивать его версию с версией приложения и предлагать перейти на страницу релизов для скачивания. Тихая установка не выполняется — пользователь скачивает и устанавливает релиз вручную.

## ADDED Requirements

### Requirement: Проверка обновлений по фиду
Приложение SHALL загружать фид обновлений — JSON вида `{version, url, notes}` — с публичного URL, встроенного в приложение, и сравнивать версию фида с текущей версией приложения (semver по трём числовым компонентам). Обновление считается доступным, если версия фида строго больше текущей.

#### Scenario: Доступна более новая версия
- **WHEN** фид содержит `version` больше текущей версии приложения (например, `0.0.2` против установленной `0.0.1`)
- **THEN** результат проверки — «обновление доступно» с версией фида, заметками `notes` и ссылкой `url` на страницу релиза

#### Scenario: Версии совпадают или фид старее
- **WHEN** версия фида равна текущей или меньше её
- **THEN** результат проверки — «обновлений нет»

#### Scenario: Некорректный или недоступный фид
- **WHEN** фид недоступен по сети, содержит не-JSON или не содержит корректной версии `x.y.z`
- **THEN** проверка завершается ошибкой, приложение продолжает работу как обычно; при автопроверке ошибка не показывается пользователю

### Requirement: Автоматическая проверка при запуске
Приложение SHALL выполнять проверку обновлений один раз за запуск вскоре после старта окна, если автоматическая проверка включена. При обнаружении новой версии приложение SHALL показать диалог обновления. Ошибки автопроверки SHALL не показывать пользователю.

#### Scenario: Новая версия при запуске
- **WHEN** приложение запущено, автопроверка включена и фид содержит более новую версию
- **THEN** после загрузки окна появляется диалог «Доступна новая версия» с номером версии

#### Scenario: Ошибка сети при автопроверке
- **WHEN** во время автопроверки фид недоступен
- **THEN** приложение продолжает работу без диалогов и сообщений об ошибке

#### Scenario: Автопроверка отключена
- **WHEN** автопроверка отключена в настройках и приложение запущено
- **THEN** проверка при запуске не выполняется

### Requirement: Ручная проверка обновлений
Приложение SHALL позволять проверить обновления вручную: пунктом меню «Проверить обновления…» и кнопкой в окне «О приложении». Результат ручной проверки SHALL всегда показываться пользователю, включая ошибки.

#### Scenario: Ручная проверка нашла обновление
- **WHEN** пользователь запускает ручную проверку и доступна более новая версия
- **THEN** открывается диалог «Доступна новая версия»

#### Scenario: Ручная проверка не нашла обновление
- **WHEN** пользователь запускает ручную проверку, а версия фида не новее текущей
- **THEN** пользователь видит сообщение «У вас установлена последняя версия»

#### Scenario: Ошибка при ручной проверке
- **WHEN** во время ручной проверки фид недоступен или некорректен
- **THEN** пользователь видит сообщение о том, что проверить обновления не удалось

### Requirement: Переход на страницу релиза
Диалог обновления SHALL показывать номер новой версии и заметки (если заданы) и SHALL предоставлять кнопку «Открыть страницу релиза», открывающую `url` из фида в системном браузере. Открытие SHALL выполняться через штатный механизм внешних ссылок приложения (только https).

#### Scenario: Открытие страницы релиза
- **WHEN** пользователь нажимает «Открыть страницу релиза» в диалоге обновления
- **THEN** системный браузер открывает страницу релиза GitVerse, диалог закрывается

#### Scenario: Закрытие диалога без перехода
- **WHEN** пользователь закрывает диалог обновления (кнопка «Закрыть» или Esc)
- **THEN** диалог закрывается, переход не выполняется, уведомление больше не показывается до следующей проверки

### Requirement: Настройка автоматической проверки
Приложение SHALL хранить настройку автоматической проверки `checkUpdates` в `settings.json`. По умолчанию автопроверка включена; отсутствие настройки в существующем файле настроек SHALL трактоваться как включённая. Переключатель настройки SHALL располагаться в окне «О приложении», изменение SHALL сохраняться в хранилище.

#### Scenario: Отключение автопроверки
- **WHEN** пользователь выключает переключатель в окне «О приложении»
- **THEN** настройка сохраняется, и при следующих запусках проверка при старте не выполняется

#### Scenario: Совместимость со старыми настройками
- **WHEN** в существующем `settings.json` нет поля `checkUpdates`
- **THEN** автопроверка считается включённой
