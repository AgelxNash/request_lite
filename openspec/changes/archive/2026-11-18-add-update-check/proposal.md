# Proposal: add-update-check

## Why

Приложение распространяется сборками с [релизов GitVerse](https://gitverse.ru/rnikolaenkov/request_lite/releases), и пользователь не имеет способа узнать, что вышла новая версия. Нужно автоматическое уведомление о новом релизе. Полноценное тихое автообновление (electron-updater) сейчас невозможно: сборки неподписанные (Squirrel.Mac на macOS требует код-подпись), а публичный API GitVerse не отдаёт релизы анонимно (требует Bearer-токен). Поэтому закладываем проверку версии + уведомление со ссылкой на релиз, с архитектурой, из которой позже без переделки UI можно перейти на electron-updater.

## What Changes

- Новый модуль проверки обновлений в main-процессе (`src/main/update-check.js`): загрузка фида `latest.json` с публичного URL, сравнение версий, сформированный результат для UI. Чистые функции (парсинг фида, сравнение версий) — без импорта Electron, тестируемые из smoke-скрипта.
- Автопроверка один раз за запуск (с задержкой после старта) при включённой настройке; проверка ошибок сети — тихая, без пугающих сообщений.
- Ручная проверка: пункт меню «Проверить обновления…» и кнопка в окне «О приложении».
- Диалог «Доступна новая версия»: номер версии, кнопка «Открыть страницу релиза» (через существующий https-only `shell:openExternal`) и «Закрыть».
- Настройка `checkUpdates` в `settings.json` (по умолчанию включена), переключатель в окне «О приложении».
- Новый IPC-префикс `updates:*` (`updates:check`, push-событие результата в renderer).
- Файл `updates/latest.json` в репозитории как источник фида: `{version, url, notes}`; публикация релизного процесса — обновлять его при выпуске каждой версии (подробности в design.md).

## Capabilities

### New Capabilities
- `update-checks`: проверка наличия новой версии приложения по публичному фиду, уведомление пользователя и переход на страницу релизов; управление автоматической проверкой.

### Modified Capabilities

(нет — требования существующих capabilities не меняются; окно «О приложении» и меню получают доп. элементы, но их существующие требования сохраняются)

## Impact

- Код: `src/main/update-check.js` (новый), `src/main/index.js` (запуск автопроверки + пункт меню), `src/main/ipc.js` (каналы `updates:*`), `src/preload/index.js` (`api.updates.*`, событие результата), `src/renderer/src/components/AboutDialog.vue` (кнопка проверки + переключатель), новый `UpdateDialog.vue`, `src/renderer/src/stores/ui.js` (состояние диалога), `src/main/storage.js` (`DEFAULT_SETTINGS.checkUpdates`), `scripts/smoke.mjs` (тесты чистых функций).
- Зависимости: новых нет — fetch из Node, сравнение версий и парсинг фида собственные.
- Хранилище: новое поле `checkUpdates` в `settings.json` (обратимо-совместимо: отсутствие поля = включено).
- Процесс релизов: при выпуске версии обновлять `updates/latest.json` и публиковать фид по публичному URL (место публикации — вне кода, см. design.md «Открытые вопросы»).
