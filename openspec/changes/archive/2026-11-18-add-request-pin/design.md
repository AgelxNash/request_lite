# Design

## Context

Модель зон уже отработана на вкладках (`add-tab-drag-and-pin`): закреплённые — префикс массива, `moveTab` зажимает целевую позицию в зону, нормализация ставит pin/unpin на край новой зоны. В сайдбаре порядок запросов теперь хранится на диске (`add-request-reorder`): массив `requests[]` в файле проекта, drag с live-swap локально и одним IPC на `pointerup`. Метаданные записи (`locked`) живут в записи, не в снимке вкладки: upsert сохраняет флаг (`requests[index] = { ...stored, locked: ... }`), новые и импортированные получают `false` — `pinned` идёт тем же путём. Разница с вкладками принципиальна: инвариант «закреплённые первыми» обязан жить в `storage.js` (диск — источник правды), а не в renderer-сторе.

## Goals / Non-Goals

**Goals:**
- Закрепление запроса кнопкой строки (без подтверждения) с persist-хранением.
- Зона закреплённых сверху; drag внутри зоны разрешён, граница зон жёсткая.
- Независимость pin и lock; upsert и импорт не трогают pin.

**Non-Goals:**
- Связь pin вкладки с pin запроса в сайдбаре (разные сущности: вкладка — runtime, запрос — диск).
- Контекстное меню строк сайдбара (нет сегодня; кнопки в строке достаточно).
- Группировка закреплённых, pin проектов/окружений, счётчик закреплённых.

## Decisions

### 1. Поле `pinned` — метаданные записи, как `locked`
В `saveRequest` `stored` не включает `pinned`; upsert переносит флаг: `requests[index] = { ...stored, locked: ..., pinned: requests[index].pinned === true }`; новые/импорт — `pinned: false`. Снимок вкладки (`toSnapshot`) не трогается — pin не часть модели запроса из вкладки. Открытие запроса из сайдбара и Save из вкладки не влияют на закрепление.

### 2. `setRequestPinned(projectId, requestId, pinned)` с нормализацией зоны
По образцу `setRequestLocked`: валидация boolean, поиск записи, смена флага, **стабильная нормализация** массива (закреплённые — префикс, относительный порядок внутри зон сохраняется; новый закреплённый встаёт после последнего закреплённого, откреплённый — перед первым обычным), атомарная запись, возврат массива. Валидация типов — та же строгость (`/boolean/`-паттерн в smoke).

### 3. Инвариант зоны — в `storage.js`, не в renderer
`reorderRequests` зажимает целевую позицию в зону источника, как `moveTab` у вкладок: закреплённый — в `[0..N-1]`, обычный — в `[N..]` (N = число закреплённых). Renderer продолжает live-swap локально, но `moveLocal` тоже зажимает в зону (дублирующая защита для визуальной честности во время drag); IPC-ответ остаётся источником правды.

### 4. Кнопка 📌 в hover-действиях строки
Четвёртая кнопка в `.project-actions` строки запроса (после замка, перед удалением): 📌/📍 по состоянию, `pointerdown.stop` (drag с кнопки не начинается — механика уже есть у замка и удаления). Без `dialog.confirm` — безобидная сортировка, как pin вкладок (решение explore-сессии). Бейдж 📌 у имени закреплённого — по образцу замка-бейджа. Двойной клик на строке остаётся свободным: click открывает запрос во вкладке, dblclick дал бы два дубля вкладки — не используется.

### 5. Drag-источник: строки обеих зон
В отличие от замка (drag вообще не начинается), закреплённая строка — drag-источник, но целевая позиция зажимается в её зону: таскается среди закреплённых, «упирается» в границу. `cursor: grab` на закреплённых остаётся. Замок и pin независимы: заблокированный + закреплённый не таскается вовсе (замок сильнее для источника), заблокированный обычный не таскается, незаблокированный закреплённый таскается в своей зоне.

## Risks / Trade-offs

- [Инвариант зоны в двух местах (storage и renderer moveLocal)] → дублирующая защита дешевле рассинхрона: во время drag list показывает честные зоны, IPC-ответ чинит всё.
- [Четыре кнопки в узкой строке сайдбара] → hover-действия появляются только при наведении, как сегодня; кнопка pin однобуквенная.
- [Старые файлы проектов без `pinned`] → `pinned === true` строго, отсутствие поля читается как `false` — миграции не нужна.
- [Смоук не покрывает renderer] → ручной e2e-чеклист (AGENTS.md), как в предыдущих UI-изменениях.

## Migration Plan

Новое поле читается дефолтом (`false`) в старых файлах — миграции нет. Откат — revert коммита. Ветка от `develop` (все зависимости смержены PR #2–#4).
