# Design

## Context

Схема файла проекта (`environments: []`, `activeEnvId: null`) заложена с каркаса. Отправка идёт через `sendActive()` → снимок → IPC; `http.js` в main работает с готовыми значениями и ничего не знает об окружениях — подстановка должна случиться до IPC, в renderer. KV-таблица (`KeyValueTable.vue`) и диалог (`AppDialog`) переиспользуются; тулбар содержит каркасный селектор (`Toolbar.vue`).

## Goals / Non-Goals

**Goals:**
- Круг: создать окружение с переменными → выбрать активным → `{{var}}` в запросе → Send с подстановкой; переключение проекта меняет список и активный выбор.

**Non-Goals:**
- Глобальные окружения, наследование, вложенная подстановка, динамические переменные и скрипты, подсветка `{{var}}` в редакторе запроса, автозамена при вводе.

## Decisions

### D1. Подстановка — чистый `lib/variables.js`
`resolvePlaceholders(text, vars)` — глобальная замена `/\{\{\s*([A-Za-z0-9._-]+)\s*\}\}/g` по словарю включённых переменных; неизвестные имена остаются как есть. Рекурсии нет: словарь строится один раз, значения вставляются литерально. Обёртка `applyEnvironment(snapshot, vars)` проходит поля: url, params (key+value), headers (key+value), body.json/text, значения body.urlencoded/form-data. Чистый модуль → smoke-тесты без Electron. Альтернатива (подстановка в main) отклонена: main не знает активное окружение, а чистая функция тестируется в Node.

### D2. Только `enabled`-переменные и приоритет
Словарь собирается из `variables.filter(v => v.enabled && v.key.trim() !== '')`. При совпадении ключей побеждает последняя (как в KV-таблицах проекта). Авто-Content-Type из `buildRequest` не подставляется — он константа по типу Body; явная строка заголовка Content-Type подставляется наравне с другими.

### D3. `sendActive` подставляет перед IPC
`sendActive()`: снимок → `applyEnvironment(snapshot, activeVariables)` → IPC. Если активного окружения нет — переменные пустой словарь, снимок уходит литерально (поведение «No Environment»). Runtime-поля в снимок не входят, ответ не затрагивается.

### D4. Хранилище: `environments[]` и `activeEnvId` per project
`saveEnvironment(projectId, environment)` — upsert по id (имя непустое), `deleteEnvironment(projectId, environmentId)` — с обнулением `activeEnvId`, если удалили активное; `setActiveEnvironment(projectId, environmentId | null)` — пишет `activeEnvId`. Все три возвращают `environments[]` проекта (единый источник правды, паттерн requests).

### D5. IPC `environments:*` и store
`environments:list|save|delete|setActive` (list возвращает `{environments, activeEnvId}`), мост `api.environments.*`. Новый `stores/environments.js`: `items`, `activeId`, `load(projectId)` — читает окружения и восстановленный `activeEnvId`; реагирует на смену активного проекта (watch, как в requests).

### D6. Тулбар и диалог управления
Селектор (`Toolbar.vue`) показывает окружения активного проекта + «No Environment» (значение null); выбор → `setActiveEnvironment`. Кнопка-шестерёнка → `EnvironmentsDialog.vue` (собственный компонент поверх `AppDialog`-подхода: собственный overlay, т.к. нужен составной UI — список + редактор): левая колонка — окружения (+ создать, ✕ удалить с confirm), правая — имя и `KeyValueTable` переменных; сохранение по кнопке (upsert). Диалог блокирует работу с окружениями при отсутствии активного проекта.

### D7. Формат имён переменных
`\{\{имя\}\}` допускает `[A-Za-z0-9._-]` (пробелы внутри плейсхолдера не резолвятся — против опечаток). Ключ переменной используется как есть (без trim при сопоставлении — trim только при проверке «непустой»), регистр учитывается.

## Risks / Trade-offs

- [Пользователь ожидает подстановку «на лету» в редакторе] → вне scope: в редакторе виден литеральный `{{var}}`, результат виден в ответе после Send.
- [Значение переменной содержит `\{\{другая\}\}`] → вставляется литерально (без рекурсии) — задокументировано в спеке.
- [Удаление активного окружения] → `activeEnvId` обнуляется хранилищем, селектор показывает «No Environment».
- [Пустой ключ переменной] → игнорируется при сборке словаря (сценарий в спеке).

## Migration Plan

Не требуется: `environments[]` уже в схеме файлов, записи отсутствуют.
