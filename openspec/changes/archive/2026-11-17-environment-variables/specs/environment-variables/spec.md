# Spec Delta

## Purpose

Переменные окружения проекта: наборы `{{имя}} → значение` принадлежат конкретному проекту, одно окружение активно в момент отправки; подстановка выполняется в момент отправки в URL, params, headers и body, неразрешённые плейсхолдеры остаются как есть.

## ADDED Requirements

### Requirement: Окружения принадлежат проекту
Приложение SHALL позволять создавать окружения (имя + таблица переменных «ключ — значение — галочка»), и каждое окружение SHALL принадлежать ровно одному проекту. Окружение SHALL удаляться по действию пользователя с подтверждением. Переменная с незаполненным ключом SHALL игнорироваться при подстановке.

#### Scenario: Создание окружения
- **WHEN** пользователь создаёт в проекте окружение `Dev` с переменными `baseUrl=http://localhost:4545` и `token=t-1`
- **THEN** окружение сохраняется в файле проекта и доступно другим запускам приложения

#### Scenario: Окружения проектов изолированы
- **WHEN** пользователь переключается на другой проект
- **THEN** в селекторе доступны только окружения выбранного проекта

#### Scenario: Удаление окружения
- **WHEN** пользователь удаляет окружение и подтверждает действие
- **THEN** окружение исчезает из списка; если оно было активным, селектор показывает «No Environment»

### Requirement: Выбор активного окружения
Тулбар SHALL позволять выбрать активное окружение из окружений активного проекта, включая вариант «No Environment». Выбор SHALL запоминаться per project и восстанавливаться при переключении проекта и при следующем запуске приложения.

#### Scenario: Выбор и восстановление
- **WHEN** пользователь выбирает в проекте активным окружение `Dev`, переключается на другой проект и возвращается
- **THEN** активным снова показывается `Dev`

#### Scenario: Активное окружение после перезапуска
- **WHEN** пользователь перезапускает приложение
- **THEN** для каждого проекта восстанавливается его сохранённый активный окружение-выбор

### Requirement: Подстановка переменных в момент отправки
При отправке значения активного окружения SHALL подставляться в строковые поля запроса: URL, ключи и значения params, ключи и значения headers, данные авторизации, тело (json/text, значения urlencoded/form-data). SHALL подставляться только включённые переменные; плейсхолдер `\{\{имя\}\}` заменяется во всех вхождениях; неразрешённые плейсхолдеры остаются как есть. Авто-Content-Type, добавляемый по типу Body, SHALL не подставляться. При активном «No Environment» запрос отправляется литерально.

#### Scenario: Подстановка в URL и headers
- **WHEN** активное окружение содержит включённые `baseUrl=http://localhost:4545` и `token=t-1`, и запрос имеет URL `{{baseUrl}}/echo` и заголовок `Authorization: Bearer {{token}}`
- **THEN** сервер получает запрос на `http://localhost:4545/echo` с заголовком `Authorization: Bearer t-1`

#### Scenario: Подстановка в params и body
- **WHEN** запрос содержит параметр `page={{page}}`, включённую переменную `page=2` и json-тело с `"{{page}}"`
- **THEN** сервер получает параметр `page=2` и тело с подставленной `2`

#### Scenario: Неразрешённый плейсхолдер остаётся
- **WHEN** запрос содержит `{{unknown}}`, а в активном окружении такой переменной нет
- **THEN** сервер получает литеральную строку `{{unknown}}`

#### Scenario: Выключенная переменная игнорируется
- **WHEN** переменная `debug=1` существует с выключенной галочкой, а запрос содержит `{{debug}}`
- **THEN** сервер получает литеральную строку `{{debug}}`

#### Scenario: No Environment
- **WHEN** в селекторе выбрано «No Environment», и запрос содержит `{{baseUrl}}`
- **THEN** сервер получает литеральную строку `{{baseUrl}}`
