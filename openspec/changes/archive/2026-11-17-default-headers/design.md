# Design

## Context

Механика заголовков с галочками уже работает: `buildRequest` пропускает строки с выключенной галочкой или пустым ключом, KV-таблица поддерживает автодобавление строк. Дефолтная вкладка создаётся с пустой таблицей Headers. Отправка идёт через `fetch`: undici сам добавляет `accept: */*`, `accept-language: *`, `sec-fetch-mode: cors`, `user-agent: node`, когда явные заголовки не заданы.

## Goals / Non-Goals

**Goals:**
- Новая вкладка получает заполненную таблицу Headers (3 включённых стандартных заголовка), счётчик активных на вкладке.

**Non-Goals:**
- Настройка набора дефолтов в UI настроек; Content-Type дефолтом; восстановление удалённых дефолтов; предзаполнение Params.

## Decisions

### D1. Дефолты — чистый модуль `lib/defaults.js`
`DEFAULT_HEADERS` — массив `{key, value, enabled: true}`: `User-Agent: PostmanLite/1.0`, `Accept: application/json`, `Accept-Language: ru-RU,ru;q=0.9`. Модуль без зависимостей — smoke-тесты импортируют его и проверяют как структуру, так и отправку (паттерн `format.js`). Альтернатива — константа внутри `stores/tabs.js` — отклонена: store тянет Pinia и не импортируется из Node.

### D2. `makeTab`: дефолты + одна пустая строка снизу
`headers: [...DEFAULT_HEADERS.map((h) => ({ ...h, id: nextRowId++ })), makeRow()]` — пустая строка сохраняет автодобавление при вводе. Дефолты — обычные строки: правка/удаление/галочка работают без специального кода. Удалённый дефолт не восстанавливается — намеренно: восстановление ломало бы пользовательский выбор.

### D3. Взаимодействие с автозаголовками undici — проверено эмпирически
undici добавляет свои `accept`/`accept-language`/`user-agent` только при отсутствии явных. Включённый дефолт заменяет автозначение без дублирования; снятая галочка (строка не отправляется) возвращает автозначение. Специального кода не требуется. `sec-fetch-mode: cors` не переопределяем — внутренний заголовок клиента.

### D4. Content-Type дефолтом не даётся
Content-Type уже ставится автоматически по типу Body (`buildRequest`), явная строка-дефолт конкурировала бы с авто-логикой и путала пользователя. Пользователь по-прежнему может добавить Content-Type строкой — она перекроет авто-значение (`userHasHeader`).

### D5. Счётчик Headers — по образцу Params
`activeHeadersCount = enabled && key !== ''` — та же формула, что у Params; бейдж рендерится в кнопке вкладки Headers (`tab-counter`), логика из `RequestEditor.vue`.

## Risks / Trade-offs

- [API ожидает отсутствие Accept-Language/конкретный Accept] → галочка снимает дефолт, возвращая автозначение; строки редактируемы.
- [undici изменит поведение автозаголовков в будущих версиях] → smoke-тест фиксирует текущее поведение (явный заголовок не дублируется) и уронится при изменении.
- [Дефолты «потеряются» при переключении вкладок] → нет: они часть стейта вкладки, как и всё остальное.

## Migration Plan

Не требуется: хранилище не трогается, существующие открытые вкладки не мутируются (дефолты только в новых).
