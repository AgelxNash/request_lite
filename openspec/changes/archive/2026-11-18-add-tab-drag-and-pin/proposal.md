# Proposal

## Why

Строка вкладок открыла полноценную работу с запросами, но порядок вкладок фиксирован порядком открытия: нельзя поставить часто используемый запрос первым или сгруппировать вкладки по задаче. Закрепление решает ту же проблему постоянно: важная вкладка должна оставаться слева и не теряться среди остальных. Обе возможности — ожидаемое поведение строки вкладок в стиле Postman/Chrome.

## What Changes

- Перетаскивание вкладок мышью для смены порядка: pointer-события с порогом ~4px (клик vs drag), вкладка следует за курсором, соседи сдвигаются; без новых зависимостей (свои pointer-события, как свой curl-парсер и подсветка JSON).
- Закреплённые вкладки живут в левой зоне строки с иконкой булавки. Граница зон жёсткая: перетаскивание работает только внутри своей зоны и не меняет закрепление (решение пересмотрено после ручной проверки — модель Chrome с откреплением перетаскиванием не прижилась).
- Pin/unpin через контекстное меню вкладки («Закрепить»/«Открепить») и двойной клик по вкладке; клик по булавке тоже открепляет.
- У закреплённой вкладки крестик скрыт; закрытие — новый пункт контекстного меню «Закрыть вкладку» (появляется у всех вкладок: сегодня закрытие только через ×).
- Закрепление — UI-состояние вкладки (`pinned`), в снимок запроса (`toSnapshot`) не попадает; вкладки по-прежнему не персистируются между запусками, поэтому pin-состояние умирает вместе с вкладкой.

Вне скоупа: session restore открытых вкладок, горячие клавиши для pin/reorder, закрытие «все кроме этой».

- `src/renderer/src/assets/style.css` — стили состояний drag/pinned.
- main-процесс, IPC-каналы, хранилище, зависимости — без изменений.
