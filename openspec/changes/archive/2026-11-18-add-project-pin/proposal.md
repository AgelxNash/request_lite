# Proposal

## Why

Важный проект нельзя зафиксировать наверху списка: перемещение есть (change `add-project-reorder`), но позицию сдвигает любой drag. Закрепление решает это так же, как для запросов (change `add-request-pin`): модель зон уже отработана дважды (вкладки, запросы) — здесь она замыкает единообразие всех трёх списков приложения.

## What Changes

- Закрепление проекта кнопкой 📌 в hover-действиях строки сайдбара (без подтверждения — безобидная сортировка, как у запросов; бейдж 📌 у имени закреплённого).
- Закреплённые проекты располагаются в верхней зоне списка до всех обычных; новый закреплённый встаёт последним среди закреплённых.
- Перетаскивание внутри зоны закреплённых разрешено; граница зон жёсткая: закреплённый проект не перетаскивается вниз к обычным, обычный не входит в зону закреплённых — закреплённый не сдвигается при drag обычных.
- Persist-поле `pinned` в записи индекса `projects.json` (метаданные, как `locked`): переживает перезапуск, переименование и смену блокировки, новые проекты и импорт коллекции создаются незакреплёнными.
- Независимость от блокировки: проект может быть закреплён и заблокирован одновременно; замок по-прежнему запрещает drag-источник полностью, pin дополнительно фиксирует позицию относительно обычных.
- IPC `projects:setPinned` + нормализация зоны в хранилище (инвариант «закреплённые первыми» живёт в `storage.js`).
- Наблюдаемое следствие (осознанное): при запуске активным становится первый проект списка — теперь это самый верхний закреплённый, если закрепление есть.

Вне скоупа: связь pin проектов и запросов, группировка закреплённых, pin окружений.

### Modified Capabilities

- `projects-management`: добавляется «Закрепление проектов» — зона, установка/снятие кнопкой, persist, независимость от блокировки; модифицируется «Перемещение проектов» — граница зон становится жёсткой (зеркально дельтам request-storage из `add-request-pin`).

- `src/renderer/src/stores/projects.js` — экшен `setPinned`, зажим в зону в `moveLocal`.
