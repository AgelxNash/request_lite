# Design

## Context

Модель зон реализована дважды: во вкладках (`add-tab-drag-and-pin`, runtime-состояние) и в запросах сайдбара (`add-request-pin`, persist). Для проектов — третий экземпляр, самый простой: порядок живёт в индексе `projects.json`, а `renameProject`/`setProjectLocked` мутируют найденную запись, не пересобирая её — `pinned` переживает их автоматически. Полный референс — `add-request-pin`: `setRequestPinned` со стабильной нормализацией, зажим в зону в `reorderRequests` и в `moveLocal`, кнопка/бейдж в `RequestList.vue`.

## Goals / Non-Goals

**Goals:**
- Закрепление проекта кнопкой строки (без подтверждения) с persist в индексе.
- Зона закреплённых сверху; drag внутри зоны разрешён, граница зон жёсткая.
- Инвариант «закреплённые первыми» в `storage.js`.

**Non-Goals:**
- Связь pin проектов и запросов (разные сущности и списки).
- Персистентность активного проекта (и так вне сущностей).
- Группировка закреплённых, pin окружений, счётчик закреплённых.

## Decisions

### 1. Поле `pinned` — метаданные записи индекса, как `locked`
`createProject` и `importCollection` создают записи с `pinned: false`. `renameProject`/`setProjectLocked` мутируют запись по месту — pin сохраняется без изменений кода (проверено чтением: обе функции правят только `name`/`locked`). `deleteProject` не зависит от pin — закрепление не защита от удаления.

### 2. `setProjectPinned(id, pinned)` с нормализацией зоны
По образцу `setRequestPinned`: валидация boolean, поиск записи, смена флага, стабильная нормализация (закреплённые — префикс; новый закреплённый после последнего закреплённого, откреплённый перед первым обычным), атомарная запись индекса, возврат массива. Валидация типов — та же строгость (`/boolean/` в smoke).

### 3. Зажим зоны — в `reorderProjects` и в `moveLocal`
`reorderProjects` зажимает целевую позицию в зону источника (закреплённый — `[0..N-1]`, обычный — `[N..]`), как `reorderRequests`. Renderer-зажим в `moveLocal` — дублирующая защита для честных зон во время drag; IPC-ответ — истина.

### 4. Кнопка 📌 между замком и переименованием
Четвёртая hover-кнопка строки (🔒/🔓, 📌/📍, ✎, ✕) с `pointerdown.stop` — drag с кнопок не начинается (механика уже у всех трёх). Бейдж 📌 у имени — общий класс `.project-lock-badge`. Без `dialog.confirm` — дефолт explore-сессии (как у запросов). Двойной клик не используется: клик выбирает активный проект, dblclick дал бы двойной выбор.

### 5. Активный проект при запуске
`projects.load()` делает активным первый проект списка — теперь это самый верхний закреплённый, если есть. Осознанное наблюдаемое следствие (закрепил — видишь при запуске), поведение не меняется.

## Risks / Trade-offs

- [Инвариант зоны в двух местах (storage и renderer)] → дублирующая защита дешевле рассинхрона (проверено в `add-request-pin`).
- [Четыре кнопки в узкой строке] → hover-действия появляются при наведении, как сегодня.
- [Старый `projects.json` без `pinned`] → `pinned === true` строго, отсутствие поля читается как `false` — миграции не нужна.
- [Смоук не покрывает renderer] → ручной e2e-чеклист (AGENTS.md).

## Migration Plan

Новое поле читается дефолтом (`false`) в старых индексах — миграции нет. Откат — revert коммита. Ветка от `develop` (зависимости — PR #2–#5 — смержены).

## Open Questions

Нет — семантика унаследована от `add-request-pin` и подтверждена пользователем («по аналогии»).
