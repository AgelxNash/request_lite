# Design

## Context

Порядок проектов — порядок массива в `projects.json` (индексе); паттерн его мутации уже есть в `renameProject` (listProjects → find → mutate → writeJsonAtomic → return записи). Каналов IPC для переупорядочивания нет (`projects:create/rename/delete/setLocked/importCollection/list`). Список рендерится в `ProjectList.vue` простым `v-for`, клик строки = `projects.select(id)`. Полный референс реализации — change `add-request-reorder`: стор с `moveLocal`/`reorder`, pointer-drag с порогом 4px и window-слушателями (без `setPointerCapture` — capture снимается неявно при DOM-перемещении узла), live-swap по серединам строк, click-гард, один IPC на `pointerup`, автоскролл rAF.

## Goals / Non-Goals

**Goals:**
- Перетаскивание строк проектов с сохранением порядка в индекс (переживает перезапуск).
- Заблокированная строка не является drag-источником; замки сдвигаются при drag других без изменения содержимого.
- Одна атомарная запись индекса на завершение drag.
- Единообразие со списком запросов — тот же pointer-drag каркас.

**Non-Goals:**
- Группы/папки проектов, сортировка по заголовку, drag окружений.
- Персистентность активного проекта (и так вне сущностей — выбирается при запуске).
- Анимации перестановки.

## Decisions

### 1. Хранилище: `reorderProjects(id, toIndex)` для индекса
По паттерну `renameProject`: `listProjects()` → валидация (`id` строка, `toIndex` целое ≥ 0; зажим в границы как у `reorderRequests`) → splice → `writeJsonAtomic(indexPath(), projects)`. Ограничений на `locked` **нет**: блокировка проекта защищает от удаления (спека projects-management), перемещение меняет только порядок массива; замок записи не трогается. Заблокированный источник отсекается на уровне UI. Возвращать обновлённый массив индекса (store не расходится с диском).

### 2. Диск — один вызов на pointerup (как у запросов)
Во время drag порядок меняется локально (`moveLocal` — splice в `projects.projects`), на отпускание — один IPC `projects:reorder`, ответ обновляет `projects`. Сбой IPC или отмена (`Escape`/`pointercancel`) → `projects.load()` (перечитывание индекса — полный откат, есть в сторе).

### 3. Drag в `ProjectList.vue` — тот же каркас, другой клик
Pointer-слой переносится из `RequestList.vue` без структурных изменений: порог 4px, window-слушатели, live-swap по вертикальным серединам, `cursor: grab` только на незаблокированных строках. Отличия:
- обычный клик строки — `select(id)` (активация проекта), поэтому click-гард после drag обязателен, иначе «брошенный» проект станет активным;
- три кнопки строки (замок, переименование, удаление) получают `pointerdown.stop` — drag с них не начинается (в запросах кнопок две, механика та же);
- пустое состояние списка («Нет проектов») drag не затрагивает.

### 4. IPC: канал `projects:reorder`
`ipcMain.handle('projects:reorder', (_e, { id, toIndex }) => storage.reorderProjects(id, toIndex))`, мост `projects.reorder(id, toIndex)`. Префикс `projects:*` соответствует конвенции AGENTS.md. Обратите внимание: остальные `projects:*` каналы передают `{ id, ... }` (не `projectId`) — имя поля сохраняется.

### 5. Автоскролл — как у запросов
rAF-паттерн у верхней/нижней границы контейнера списка проектов; срабатывает только при переполнении (обычно проектов мало — при нулевом скролле безвреден).

## Risks / Trade-offs

- [click после drag делает «брошенный» проект активным] → флаг-гард в select-обработчике (в запросах то же решение).
- [Расхождение `projects` с индексом во время drag] → окно до pointerup — доли секунды; сбой закрывается `load()`; параллельных писателей индекса в процессе нет.
- [Мало проектов — drag почти не нужен] → осознанный cost: единообразие списков outweighs; код — прямая копия отлаженного каркаса.
- [Смоук не покрывает renderer] → ручной e2e-чеклист (AGENTS.md), как в предыдущих UI-изменениях.

## Migration Plan

Новый канал и функция; индекс не меняет схему записей. Откат — revert коммита. Ветка от `develop` (все зависимости — `add-request-reorder` — уже смержены PR #3).
