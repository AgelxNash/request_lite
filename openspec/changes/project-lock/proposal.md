# Proposal

## Why

Удаление проекта необратимо (файл с запросами и окружениями стирается) — достаточно случайного клика по ✕ с машинально подтверждённым диалогом. Блокировка даёт явную защиту: важный проект (эталонные запросы, рабочие окружения) помечается как неудаляемый.

## What Changes

- Модель: `locked: boolean` в записи индекса `projects.json` (метаданные уровня индекса; по умолчанию `false`).
- Хранилище: `setProjectLocked(id, locked)`; guard в `deleteProject` — заблокированный проект не удаляется (защита на уровне main, даже минуя UI).
- IPC: канал `projects:setLocked {id, locked}` → обновлённая запись проекта; `projects:list` отдаёт `locked` как часть записи.
- UI сайдбара: третья кнопка-замок в actions строки проекта (переключает блокировку), 🔒-индикатор у имени заблокированного проекта, кнопка ✕ неактивна с подсказкой «Проект заблокирован».
- Переключение блокировки — через окно подтверждения (AppDialog.confirm) в обе стороны: «Заблокировать проект …?» / «Разблокировать проект …?».
- Блокировка влияет только на удаление: переименование и работа с запросами/окружениями не ограничиваются.

Вне scope: блокировка запросов и окружений по отдельности; пароль на разблокировку; блокировка по умолчанию; индикаторы в тулбаре/редакторе.

### Modified Capabilities

- `projects-management`: ADDED требования «Блокировка проекта» (переключение с подтверждением, персистентность, индикатор, влияние только на удаление) и MODIFIED «Удаление проекта» (заблокированный проект не удаляется: кнопка неактивна, хранилище отклоняет удаление).

## Impact

- `src/main/storage.js` — `setProjectLocked`, guard в `deleteProject`, `locked` в записи при создании.
- `src/main/ipc.js`, `src/preload/index.js` — канал `projects:setLocked`, `api.projects.setLocked`.
- `src/renderer/src/components/ProjectList.vue` — кнопка-замок, индикатор, неактивная ✕.
- `src/renderer/src/stores/projects.js` — action `setLocked`.
- `scripts/smoke.mjs` — тесты флага и guard'а.
- Зависимости не добавляются.
