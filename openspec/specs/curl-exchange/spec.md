# curl-exchange Specification

## Purpose

Обмен запросами в формате curl: парсинг команды curl в снимок запроса (импорт в новую вкладку) и генерация команды из снимка запроса (экспорт с копированием в буфер). Конвертация выполняется в обе стороны без потери данных запроса; переменные `{{var}}` переносятся литерально.

## Requirements

### Requirement: Токенизация команды curl
Парсер SHALL токенизировать команду как shell: одинарные кавычки — литерально, двойные — с обработкой `\"` и `\\`, `\x` вне кавычек — литеральный `x`, `\` в конце строки — перенос команды. Ведущий `curl` (включая полный путь) отбрасывается; URL — позиционный http/https-аргумент или `--url`; неизвестные флаги пропускаются. Команда без URL SHALL давать понятную ошибку в диалоге без создания вкладки.

#### Scenario: Импорт типичной команды
- **WHEN** пользователь вставляет `curl -X POST 'https://api.example.com/users' -H 'Authorization: Bearer t-1' -H 'Content-Type: application/json' -d '{"name":"Ann"}'` и подтверждает импорт
- **THEN** открывается новая вкладка: метод POST, URL без кавычек, два заголовка, тело json с `Content-Type: application/json`

#### Scenario: Ошибка без URL
- **WHEN** пользователь вставляет текст без URL (например, только `curl -X GET`)
- **THEN** диалог показывает понятное сообщение об ошибке, новая вкладка не создаётся

#### Scenario: Многострочная команда с переносами
- **WHEN** пользователь вставляет команду, разбитую `\` на несколько строк
- **THEN** команда разбирается как одна

### Requirement: Семантика флагов curl при импорте
Парсер SHALL конвертировать флаги в поля запроса: `-X/--request` (включая слитные `-XPOST` и `--request=POST`) — метод; `-H/--header` — заголовки; `-d/--data/--data-raw/--data-binary` — тело (при `-d` без явного метода — POST); `--json` — тело json с `Content-Type: application/json`; `-F/--form` — тело form-data (поле `name=@path` импортируется с литеральным значением `@path`); `-u/--user` — auth basic; `-b/--cookie` — заголовок Cookie; `-G/--get` — метод GET с данными `-d` в query-параметрах.

#### Scenario: -d без метода даёт POST
- **WHEN** пользователь импортирует `curl https://api.example.com -d 'a=1&b=2'`
- **THEN** вкладка имеет метод POST и тело `a=1&b=2`

#### Scenario: -u и -b конвертируются
- **WHEN** пользователь импортирует `curl -u user:pass -b 'k=v' https://api.example.com`
- **THEN** вкладка имеет auth basic (логин `user`, пароль `pass`) и заголовок `Cookie: k=v`

#### Scenario: -G переносит данные в query
- **WHEN** пользователь импортирует `curl -G https://api.example.com -d 'page=2' -d 'limit=10'`
- **THEN** вкладка имеет метод GET, URL `https://api.example.com` и params `page=2`, `limit=10`

#### Scenario: Слитная форма флага
- **WHEN** пользователь импортирует `curl -XPOST https://api.example.com`
- **THEN** вкладка имеет метод POST

### Requirement: Импорт в новую вкладку
Успешный импорт SHALL открывать запрос новой вкладкой, не связанной с сохранённым запросом; имя — подсказка из URL.

#### Scenario: Результат импорта
- **WHEN** пользователь подтверждает импорт корректной команды
- **THEN** открывается новая вкладка с содержимым команды, не связанная с сохранённым запросом

### Requirement: Экспорт запроса в команду curl
Контекстное меню вкладки (правый клик по любой вкладке) SHALL содержать пункт «Копировать как cURL», строящий команду из снимка вкладки: не-GET метод → `-X`; заголовки → `-H`; bearer → заголовок `Authorization`, apikey → заголовок или query, basic → `-u`; тело json/text → `-d` с `Content-Type`, urlencoded → `--data-urlencode` на пару, form-data → `-F`; значения — в одинарных кавычках с экранированием `'` → `'\''`; переменные `{{var}}` — литерально.

#### Scenario: Экспорт запроса с auth и телом
- **WHEN** пользователь открывает меню вкладки с методом POST, URL `https://api.example.com`, bearer-токеном `t-1` и json-телом и выбирает «Копировать как cURL»
- **THEN** панель показывает команду с `-X POST`, `-H 'Authorization: Bearer t-1'` и `-d '{"…"}'` с `-H 'Content-Type: application/json'`

#### Scenario: Экспорт basic-авторизации
- **WHEN** пользователь экспортирует вкладку с auth basic (логин `user`, пароль `p@ss`)
- **THEN** команда содержит `-u 'user:p@ss'`

#### Scenario: Экранирование кавычек
- **WHEN** экспортируемое значение содержит одинарную кавычку
- **THEN** в команде кавычка экранирована как `'\''`, и команда корректно выполняется в shell

#### Scenario: Переменные литерально
- **WHEN** пользователь экспортирует вкладку с URL `{{baseUrl}}/echo`
- **THEN** команда содержит литеральный `{{baseUrl}}`, а не значение активного окружения

### Requirement: Панель экспорта с копированием
Пункт «Копировать как cURL» SHALL открывать панель-шторку справа с командой в код-блоке: текст доступен для выделения; кнопка «Копировать» SHALL помещать команду в системный буфер обмена; панель закрывается по кнопке и по Esc.

#### Scenario: Копирование в буфер
- **WHEN** пользователь нажимает «Копировать» в панели экспорта
- **THEN** команда помещается в системный буфер обмена

#### Scenario: Закрытие панели
- **WHEN** пользователь закрывает панель кнопкой или Esc
- **THEN** панель исчезает, содержимое вкладки и ответ не затронуты

### Requirement: Круговая конвертация без потерь
Для любого снимка запроса последовательность «экспорт в curl → импорт команды» SHALL воспроизводить метод, URL (включая параметры), заголовки, тело (тип и содержимое) и auth.

#### Scenario: Round-trip
- **WHEN** запрос с params, заголовками, urlencoded-телом и basic-авторизацией экспортируется в curl, а команда импортируется обратно
- **THEN** новая вкладка содержит те же метод, URL с параметрами, заголовки, тело и авторизацию
