# mcp-server Specification

## Purpose

Внешний программный интерфейс приложения для ИИ-агентов: локальный MCP-сервер (Streamable HTTP на localhost) открывает агентам просмотр проектов, запросов и окружений, изменение записей с уважением к блокировке, отправку HTTP-запросов штатным движком и обмен curl — под локальным биндом и токеном доступа.

## Requirements

### Requirement: Включение сервера явной настройкой
MCP-сервер SHALL быть выключен по умолчанию и включаться только явным действием пользователя в настройках. Во включённом состоянии сервер SHALL слушать только `127.0.0.1` на порту из настроек; выключение SHALL прекращать слушать порт. После перезапуска приложения состояние сервера SHALL соответствовать сохранённой настройке.

#### Scenario: По умолчанию выключен
- **GIVEN** настройки не содержат секции MCP-сервера
- **THEN** порт не слушается, подключение агента отклоняется

#### Scenario: Включение открывает порт
- **WHEN** пользователь включает MCP-сервер на странице настроек
- **THEN** приложение начинает принимать соединения на `127.0.0.1:<порт>`

#### Scenario: Выключение закрывает порт
- **WHEN** пользователь выключает MCP-сервер
- **THEN** порт перестаёт слушаться, активные соединения закрываются

### Requirement: Токен доступа
При первом включении сервера приложение SHALL генерировать случайный токен и сохранять его в настройках. Запросы к серверу без заголовка `Authorization: Bearer <токен>` с корректным значением SHALL отклоняться с ошибкой авторизации до выполнения какой-либо логики. Токен SHALL отображаться пользователю в блоке информации о подключении на странице настроек для переноса в конфигурацию ИИ-клиента.

#### Scenario: Первый запуск генерирует токен
- **WHEN** пользователь включает MCP-сервер впервые
- **THEN** в настройках появляется сгенерированный токен, видимый в UI

#### Scenario: Запрос без токена отклоняется
- **WHEN** клиент обращается к серверу без заголовка авторизации или с неверным токеном
- **THEN** сервер возвращает ошибку авторизации, инструменты не вызываются

#### Scenario: Запрос с корректным токеном проходит
- **WHEN** клиент обращается с корректным `Authorization: Bearer <токен>`
- **THEN** запрос обрабатывается по правилам протокола MCP

### Requirement: Транспорт Streamable HTTP и рукопожатие
Сервер SHALL принимать JSON-RPC 2.0 запросы методом HTTP POST на эндпоинт `/mcp` и отвечать `application/json`. На `initialize` сервер SHALL отвечать версией протокола, capabilities с поддержкой инструментов и именем/версией приложения; уведомления (запросы без `id`) SHALL подтверждаться успешным пустым ответом. Методы `tools/list` и `tools/call` SHALL работать согласно схемам инструментов; неизвестный метод SHALL возвращать JSON-RPC ошибку.

#### Scenario: Рукопожатие initialize
- **WHEN** клиент отправляет `initialize` с версией протокола и клиентской информацией
- **THEN** сервер отвечает версией протокола, `capabilities.tools` и `serverInfo` с именем и версией приложения

#### Scenario: Список инструментов
- **WHEN** клиент вызывает `tools/list`
- **THEN** сервер возвращает все инструменты с именем, описанием и JSON-схемой входа

#### Scenario: Неизвестный метод
- **WHEN** клиент вызывает неизвестный метод
- **THEN** сервер возвращает JSON-RPC ошибку «метод не найден»

### Requirement: Инструменты просмотра данных
Сервер SHALL предоставлять инструменты чтения: список проектов, список запросов проекта, содержимое запроса, список окружений проекта с активным. Данные SHALL возвращаться как JSON, отражающий записи на диске (включая `locked`/`pinned`), в порядке хранения. Обращение к несуществующему проекту или запросу SHALL возвращать понятную ошибку, а не пустой результат.

#### Scenario: Список проектов
- **WHEN** агент вызывает инструмент списка проектов
- **THEN** ответ содержит все проекты с их идентификаторами, именами и флагами блокировки/закрепления

#### Scenario: Запросы и окружения проекта
- **WHEN** агент запрашивает запросы и окружения существующего проекта
- **THEN** ответ содержит записи в порядке хранения и помеченное активное окружение

#### Scenario: Несуществующий идентификатор
- **WHEN** агент обращается к инструменту с идентификатором несуществующего проекта
- **THEN** ответ содержит ошибку «не найдено», данные не изменяются

### Requirement: Изменение записей с уважением к блокировке
Сервер SHALL предоставлять инструменты создания, обновления и удаления запросов в проекте и выбора активного окружения. Обновление и удаление заблокированного запроса SHALL отклоняться ошибкой, как в штатном UI; создание запросов не ограничивается блокировкой. Проекты и окружения как структуры (создание/удаление/переименование проектов) через MCP не предоставляются — они остаются делом пользователя.

#### Scenario: Создание и обновление запроса
- **WHEN** агент создаёт запрос и затем обновляет его поля
- **THEN** запрос появляется в проекте и обновляется, порядок остального списка не меняется

#### Scenario: Заблокированный запрос защищён
- **WHEN** агент пытается обновить или удалить заблокированный запрос
- **THEN** инструмент возвращает ошибку блокировки, запись остаётся неизменной

#### Scenario: Выбор активного окружения
- **WHEN** агент выбирает существующее окружение проекта активным
- **THEN** последующие отправки через MCP используют переменные этого окружения, как и отправки из UI

### Requirement: Отправка запросов через инструменты
Сервер SHALL предоставлять отправку сохранённого запроса (с подстановкой переменных активного окружения) и произвольного запроса по методу, URL, заголовкам и телу. Результат SHALL содержать статус, время, размер, заголовки и тело; тело SHALL урезаться до разумного размера с пометкой, а таймаут, отмена и сетевые ошибки SHALL возвращаться текстом ошибки. Отправка сохранённого запроса SHALL сохранять ответ в его историю (capability `response-history`); произвольный запрос историю не пишет.

#### Scenario: Отправка с переменными окружения
- **GIVEN** сохранённый запрос содержит `{{baseUrl}}` в URL, активное окружение задаёт `baseUrl`
- **WHEN** агент отправляет сохранённый запрос
- **THEN** сервер получает URL с подставленным значением, агент получает статус и тело ответа

#### Scenario: Таймаут возвращается ошибкой
- **WHEN** целевой сервер не отвечает в течение лимита
- **THEN** агент получает текст ошибки таймаута, соединение MCP сохраняется

#### Scenario: Большое тело усечено
- **WHEN** ответ содержит тело больше передаваемого лимита
- **THEN** агент получает начало тела с явной пометкой об усечении и фактическом размере

#### Scenario: send_request пишет историю
- **GIVEN** сохранённый запрос в проекте без истории
- **WHEN** агент отправляет его через `send_request` и получает ответ
- **THEN** ответ дописан в историю запроса на диске, как при отправке из UI

#### Scenario: Ошибка отправки историю не меняет
- **WHEN** отправка сохранённого запроса через `send_request` завершается таймаутом
- **THEN** история запроса остаётся без изменений

### Requirement: Curl-инструменты
Сервер SHALL предоставлять разбор строки curl в снимок запроса (без отправки и без сохранения — агент решает сам) и генерацию curl из сохранённого запроса. Разбор SHALL поддерживать те же флаги, что и встроенный парсер приложения, включая метод по умолчанию POST при наличии тела.

#### Scenario: Импорт curl без сохранения
- **WHEN** агент передаёт строку curl с флагами `-X POST -H -d`
- **THEN** инструмент возвращает снимок запроса с методом POST, заголовками и телом, записи на диске не меняются

#### Scenario: Экспорт curl
- **WHEN** агент запрашивает curl существующего запроса
- **THEN** инструмент возвращает корректно экранированную строку curl, пригодную для запуска в shell

### Requirement: Страница настроек MCP-сервера
Приложение SHALL иметь страницу настроек, на которой размещаются параметры MCP-сервера. Параметров на странице SHALL быть ровно два: включение сервера (по умолчанию выключен) и порт сервера (по умолчанию 45460). Изменение порта SHALL применяться перезапуском слушателя без перезапуска приложения.

#### Scenario: Два параметра на странице настроек
- **WHEN** пользователь открывает страницу настроек
- **THEN** на ней отображаются только тумблер включения MCP-сервера (выключен по умолчанию) и поле порта (45460 по умолчанию)

#### Scenario: Смена порта на лету
- **WHEN** пользователь меняет порт включённого сервера
- **THEN** слушатель перезапускается на новом порту без перезапуска приложения

### Requirement: Информация о подключении при включённом сервере
При включённом сервере на странице настроек SHALL отображаться блок информации о подключении: фактическое состояние, адрес и токен с возможностью копирования, а также готовый фрагмент конфигурации для вставки в ИИ-клиент. Блок не является настройкой и SHALL скрываться при выключении сервера.

#### Scenario: Блок информации о подключении
- **WHEN** пользователь включает сервер на странице настроек
- **THEN** на странице появляется блок информации о подключении: состояние «включён», адрес с портом, токен и конфигурационный фрагмент для клиента

#### Scenario: Скрытие блока при выключении
- **WHEN** пользователь выключает сервер
- **THEN** блок информации о подключении исчезает
