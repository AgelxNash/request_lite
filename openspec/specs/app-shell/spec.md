# app-shell Specification

## Purpose

Окно, меню и раскладка интерфейса приложения в стиле Postman: тулбар, сайдбар проектов, редактор запроса и область ответа. Capability описывает каркасный уровень интерфейса, на котором последующие изменения наращивают логику запросов, окружений и импорта.

## Requirements

### Requirement: Окно и раскладка в стиле Postman
Приложение SHALL открывать главное окно с раскладкой из трёх зон: тулбар сверху, сайдбар проектов слева, основная область (редактор запроса + область ответа) справа.

#### Scenario: Первый запуск на пустом хранилище
- **WHEN** пользователь запускает приложение, а папка хранилища пуста
- **THEN** окно открывается с полной раскладкой, сайдбар показывает пустое состояние с приглашением создать проект

#### Scenario: Состав тулбара
- **WHEN** пользователь смотрит на тулбар
- **THEN** в нём видны название приложения, рабочий селектор окружения (окружения активного проекта и «No Environment») с кнопкой управления окружениями, кнопка переключения темы

### Requirement: Меню приложения
Приложение SHALL иметь меню с пунктами New Project и Open data folder.

#### Scenario: New Project из меню
- **WHEN** пользователь выбирает пункт меню New Project
- **THEN** создаётся новый проект, который появляется в сайдбаре

#### Scenario: Open data folder из меню
- **WHEN** пользователь выбирает пункт меню Open data folder
- **THEN** системный файловый менеджер открывает папку хранилища приложения

### Requirement: Редактор и ответ как каркасные зоны
Основная область SHALL показывать строку вкладок открытых запросов, строку метод + URL + Save + Send, вкладки запроса (Params, Headers, Body, Auth) и область ответа. Поведение вкладок запроса, сохранения и отправки определяется capabilities `request-storage` и `request-execution`; данное требование описывает только состав и раскладку зон.

#### Scenario: Вкладка открытого запроса
- **WHEN** открыта одна стартовая вкладка запроса
- **THEN** она отображается на строке вкладок и может быть закрыта

#### Scenario: Пустое состояние до логики запросов
- **WHEN** пользователь открывает основную область до первой отправки запроса
- **THEN** вкладки запроса отображаются, а область ответа показывает пустое состояние

#### Scenario: Состав основной области
- **WHEN** пользователь открывает основную область
- **THEN** строка метод + URL + Save + Send, вкладки запроса и область ответа отображаются друг под другом

### Requirement: Перетаскивание вкладок
Пользователь SHALL иметь возможность менять порядок вкладок перетаскиванием: итоговый порядок соответствует позиции отпускания кнопки мыши. Начало перетаскивания SHALL отличаться от клика порогом перемещения: короткое нажатие остаётся активацией вкладки. Порядок SHALL сохраняться при переключении и закрывании других вкладок. При переполнении строки перетаскивание к краю SHALL прокручивать полосу вкладок.

#### Scenario: Перестановка вкладки на новое место
- **WHEN** пользователь перетаскивает вкладку на позицию другой вкладки и отпускает кнопку
- **THEN** вкладка занимает новую позицию между соседними вкладками и остаётся активной

#### Scenario: Клик не является перетаскиванием
- **WHEN** пользователь нажимает кнопку мыши на вкладке и отпускает её без заметного перемещения
- **THEN** вкладка активируется, порядок не меняется

#### Scenario: Перетаскивание при переполнении строки
- **WHEN** вкладки не помещаются в строку, и пользователь перетаскивает вкладку к левому или правому краю строки
- **THEN** строка прокручивается, позволяя довести вкладку до скрытых позиций

### Requirement: Закрепление вкладок
Пользователь SHALL иметь возможность закрепить вкладку. Закреплённая вкладка SHALL располагаться в начале строки до всех обычных вкладок и SHALL отображаться с иконкой закрепления вместо крестика закрытия. Закрепление и открепление SHALL выполняться из контекстного меню и двойным кликом по вкладке; открепление — также кликом по иконке закрепления. Закреплённая вкладка SHALL закрываться из контекстного меню. Закрепление SHALL быть состоянием интерфейса, не входящим в сохраняемый снимок запроса.

#### Scenario: Закрепление через контекстное меню
- **WHEN** пользователь выбирает «Закрепить» в контекстном меню обычной вкладки
- **THEN** вкладка перемещается в начало строки, отображается с иконкой закрепления, крестик закрытия скрыт

#### Scenario: Открепление двойным кликом
- **WHEN** пользователь дважды кликает по закреплённой вкладке
- **THEN** вкладка открепляется и занимает место среди обычных вкладок

#### Scenario: Открепление кликом по иконке
- **WHEN** пользователь кликает по иконке закрепления на закреплённой вкладке
- **THEN** вкладка открепляется

#### Scenario: Закрытие закреплённой вкладки
- **WHEN** пользователь выбирает «Закрыть вкладку» в контекстном меню закреплённой вкладки
- **THEN** вкладка закрывается, активной становится соседняя вкладка

#### Scenario: Сохранение закреплённой вкладки
- **WHEN** пользователь сохраняет закреплённую вкладку в проект и затем открывает этот запрос из сайдбара
- **THEN** запрос открывается в новой вкладке без закрепления

### Requirement: Перетаскивание и зоны закрепления
Перетаскивание SHALL менять порядок только внутри своей зоны: закреплённая вкладка при перетаскивании остаётся закреплённой и не покидает зону закреплённых, обычная не попадает в неё. Граница зон SHALL быть жёсткой: при попытке перетащить вкладку через границу вкладка остаётся по свою сторону, закрепление не меняется. Закрепление и открепление перетаскиванием не выполняются.

#### Scenario: Граница зон жёсткая
- **WHEN** пользователь перетаскивает закреплённую вкладку вправо к обычным вкладкам, либо обычную вкладку влево к закреплённым, и отпускает кнопку
- **THEN** закрепление вкладки не меняется, вкладка остаётся по свою сторону границы

#### Scenario: Перестановка среди закреплённых
- **WHEN** пользователь перетаскивает закреплённую вкладку на позицию другой закреплённой
- **THEN** порядок закреплённых вкладок меняется, обе остаются закреплёнными

### Requirement: Переименование вкладок
Пользователь SHALL иметь возможность переименовать вкладку из контекстного меню («Переименовать») и двойным кликом по имени вкладки; двойной клик по остальной части вкладки сохраняет своё действие (закрепление/открепление). Переименование SHALL открывать диалог с текущим именем; пустое имя и отмена не меняют вкладку. Переименование SHALL помечать вкладку индикатором несохранённых изменений и не SHALL затрагивать сохранённый запрос до сохранения вкладки.

#### Scenario: Переименование из контекстного меню
- **WHEN** пользователь выбирает «Переименовать» в контекстном меню вкладки и вводит новое имя
- **THEN** имя вкладки меняется, на ней отображается индикатор несохранённых изменений

#### Scenario: Двойной клик по имени вкладки
- **WHEN** пользователь дважды кликает по имени вкладки
- **THEN** открывается диалог переименования, закрепление/открепление не выполняется

#### Scenario: Двойной клик вне имени
- **WHEN** пользователь дважды кликает по части вкладки вне имени
- **THEN** выполняется закрепление/открепление вкладки, диалог переименования не открывается

#### Scenario: Отмена и пустое имя
- **WHEN** пользователь отменяет диалог переименования или подтверждает пустое имя
- **THEN** имя вкладки не меняется, индикатор не появляется

#### Scenario: Переименование не затрагивает сохранённый запрос
- **WHEN** пользователь переименовывает вкладку, связанную с сохранённым запросом, и не сохраняет её
- **THEN** запрос в сайдбаре остаётся со старым именем; новое имя попадёт в запрос при последующем сохранении вкладки
